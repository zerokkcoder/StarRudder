# 星舵 StarRudder · 设计交互规范

> 版本 1.2 · 设计概念：**极紧凑中文索引（Dense Chinese Index）**
> v1.2 变更：主内容收窄至 980px、侧栏 176px；首页首屏即资讯列表；全站 UI 文案中文化，去除中英混排；各页面行高与间距再次收紧。
> v1.1 变更：压缩留白与行高、提高信息密度；加入指针跟随聚光、交互式罗盘、随机发现、键盘检索等惊喜交互。v1.0 的视觉语言（单强调色、细线、等宽编号、无阴影）保持不变。
> 目标：区别于常见的「居中 Hero + 圆角卡片网格」导航站，建立一套像**航海图 + 图书馆索引**一样克制、可辨识、可长期演进的视觉与交互语言。

---

## 1. 设计哲学

1. **索引优先，而非卡片优先**：站点是「条目」，不是「商品卡」。用编号、细线、对齐的栏位建立秩序感，内容密度低但信息密度高。
2. **一张海图，不是一面墙**：页面有坐标感、方位感、层级感；用左侧固定「导航轨道」替代通用顶部导航栏，让浏览像在查海图。
3. **留白是主角**：大面积暖白纸面，仅用细线划分区域；不用阴影、渐变、彩色色块制造层次。
4. **单一强调色**：全站只有「星舵蓝」作为强调色，其余为中性灰阶。所有状态（hover / focus / active）都靠线条、位移、颜色深浅表达。
5. **内容必须对爬虫可见**：所有条目都是真实链接与文本，视觉效果只通过 CSS 增强，不把内容藏进 JS 才渲染的容器。

## 2. 视觉语言

### 2.1 色彩令牌

| 用途 | 浅色 | 深色 | 说明 |
|---|---|---|---|
| 纸面 `background` | `#FAF9F6` | `#141414` | 暖白 / 墨黑 |
| 墨色 `foreground` | `#1C1C1A` | `#EDEDEB` | 正文 |
| 次级 `muted-foreground` | `#73736D` | `#A1A19B` | 说明文字 |
| 星舵蓝 `primary` | `#2E4A8F` | `#8FA9E8` | 唯一强调色 |
| 细线 `border` | `rgba(28,28,26,.12)` | `rgba(255,255,255,.14)` | 1px hairline |
| 索引底 `muted` | `#F2F1ED` | `#222222` | 编号、标签底 |

**禁止**：渐变背景、彩色光晕、>1px 的边框堆叠、大面积投影。卡片 hover 仅允许 `border-color` 变化、1–2px 位移、极轻阴影（可选）。

### 2.2 字体

- 正文 / UI：**Inter Variable**（本地 `@fontsource-variable/inter`），中文回退到系统无衬线。
- 编号 / 坐标 / 域名 / 元数据：**等宽字体**（`ui-monospace, SFMono-Regular, Consolas, monospace`），制造"航海仪器"感。
- 标题：继承 Inter，字重 600–650，字距 `-0.03em`，行高 `1.1`。
- 不使用装饰性字体，不滥用斜体。

### 2.3 间距与尺度

- 基准网格 4px；间距使用 4 的倍数。
- 主内容最大宽度 1120px；桌面左侧导航轨道宽 232px。
- 区块上下留白：桌面 96–128px，移动 64px。
- 索引行高：64–72px；细线分隔，不用卡片间距。

### 2.4 形状

- 圆角：全局 `--radius: 4px`（小圆角）；仅「罗盘 / 圆形标记 / 头像字母」使用正圆。
- 图标：线性、1.5px stroke、16–18px；禁止实心彩色图标。
- 背景纹理：仅 Hero 区域允许极淡的点阵 / 网格（透明度 ≤ 4%），像海图纸。

## 3. 布局系统

### 3.1 桌面（≥ 1024px）

```
┌──────────────┬────────────────────────────────────────┐
│              │                                        │
│  SIDE RAIL   │  MAIN CONTENT                          │
│  232px fixed │  max-width 1120px, px 64               │
│              │                                        │
│  ◎ 星舵       │  01 / HERO（编辑式大标题 + 罗盘）      │
│              │  ──────────────────────────            │
│  01 首页      │  02 / 精选索引（编号列表）             │
│  02 站点      │  ──────────────────────────            │
│  03 资讯      │  03 / 航海日志（资讯列表）             │
│  04 友链      │  ──────────────────────────            │
│              │  04 / 友链（行内文本）                  │
│  ⌘K 搜索     │                                        │
│  主题切换     │  COLOPHON / 页脚                       │
└──────────────┴────────────────────────────────────────┘
```

- 左侧轨道固定（`position: fixed`），含品牌罗盘、编号导航、搜索入口、主题切换、版权简写。
- 主内容用 `margin-left: 232px`，顶部不需要 sticky header。
- 每个章节带一个「章节号 + 英文小标 + 细线」的章节头。

### 3.2 移动端（< 1024px）

- 左侧轨道折叠为顶部细条：罗盘 + 站名 + 搜索 + 主题；导航改为横向滚动的编号标签。
- 主内容全宽，边距 20px。
- 罗盘缩小为装饰元素，不参与交互。
- 索引行改为两行布局（编号 / 名称 + 描述），标签可换行。

## 4. 组件规范

### 4.1 品牌罗盘（Compass Mark）

- 线性圆 + 四向刻度 + 指针菱形；浅色底深蓝线，深色反相。
- 桌面 Hero 右侧放置大号罗盘（220–280px），四个方位点对应四个分类，点击跳转到 `/sites?category=xxx`。
- 缓慢旋转动画 60s/圈（`prefers-reduced-motion` 下停止）。

### 4.2 索引行（Ledger Row）

站点列表的标准单元，取代卡片：

```
01  ┌─┐  ChatGPT                                   AI · 写作      ↗
    └─┘  chatgpt.com — OpenAI 推出的对话式 AI 助手…
```

- 栏位：序号（等宽，muted）→ 字母方块（40px，细边框）→ 名称 + 域名（等宽小字）→ 描述（1 行截断）→ 标签 → 外链箭头。
- 行间 1px 细线；hover：整行背景 `accent/40`，序号变蓝，箭头右移 4px 并变蓝。
- 行本身是 `<a href="/go/{slug}">` 真实链接（点击计数跳转），内容始终在 DOM 中。

### 4.3 分类筛选（Bearing Tabs）

- 横向编号标签：`ALL 06 / AI TOOLS 03 / DESIGN 01 …`
- 选中态：底部 2px 蓝色下划线 + 文字变蓝；非选中为 muted。
- 实现为链接（`/sites?category=ai-tools`），服务端过滤，保证每个分类都是可索引 URL。

### 4.4 资讯条目（Journal Entry）

- 日期用等宽数字独占左栏（80px）。
- 标题 17–18px / 500；摘要单行截断；标签小号。
- 首条资讯可加「FEATURED」标记，但不放大成卡片。

### 4.5 友链（Friends）

- 不用 pill 胶囊。用「名称 / 描述」的紧凑两栏列表，名称后带 `↗`， hovering 时下划线。

### 4.6 命令搜索（⌘K Palette）

- 弹窗保持矩形小圆角，顶部等宽提示 `SEARCH / 索引检索`。
- 结果行带 `01 / 02 / 03` 等宽序号，与索引行视觉一致。
- 键盘：⌘K / Ctrl+K 打开，Esc 关闭，方向键选择，Enter 打开。

### 4.7 按钮

- 主按钮：星舵蓝底白字，小圆角，无阴影；hover 加深。
- 次按钮：透明底 + 1px 边框；hover 边框变蓝。
- 文字按钮：仅下划线偏移；不放大写。

## 5. 交互规范

| 交互 | 行为 |
|---|---|
| 索引行 hover | 背景微亮、序号变蓝、箭头右移 4px；150ms ease-out |
| 罗盘 hover | 暂停旋转，指针指向最近方位点；移出恢复 |
| 章节滚动 | 左侧轨道对应项高亮（IntersectionObserver） |
| 分类切换 | 服务端过滤 + 页面整体淡入 200ms；URL 带 query 可分享 |
| ⌘K | 打开搜索；输入即时过滤；Esc 关闭 |
| 点击站点 | 经 `/go/{slug}` 记录点击后 302 到目标站（新标签页） |
| 主题切换 | 写 localStorage，切换 `.dark`，无闪烁（suppressHydrationWarning） |
| 表单提交 | Server Action + 成功/失败行内状态，不弹窗 |

### 动效原则

- 只允许 `opacity`、`transform`、`border-color`、`background-color` 变化。
- 时长 120–240ms，`cubic-bezier(.22,.61,.36,1)`。
- `prefers-reduced-motion: reduce` 时全部关闭（含罗盘旋转与入场动画）。

### 可访问性（A11y）

- 所有交互元素有可见 focus ring（2px 星舵蓝）。
- 链接文本自解释，不用「点击这里」。
- 章节使用 `<section aria-labelledby>`；导航使用 `<nav aria-label>`。
- 颜色对比度 ≥ 4.5:1；等宽小字不小于 11px。

---

## 6. SEO 约束

- 章节顺序即信息层级：`h1`（首页主张）→ `h2`（章节）→ `h3`（条目）。
- 站点列表、资讯列表是服务器渲染的真实 `<ul><li><a>`，分类过滤用 URL query，可被抓取。
- `/go/{slug}` 返回 302，不参与索引（robots 禁止 `/go/`）。
- 每页 metadata + JSON-LD 保持现有实现，不因视觉改版退化。

## 6.1 v1.1 紧凑化与惊喜交互

### 紧凑化规则

| 项目 | v1.0 | v1.1 |
|---|---|---|
| 区块上下留白 | 96–128px | 56–80px |
| Hero 上下留白 | 128–160px | 72–96px |
| 索引行高度 | 64–72px | 56–60px |
| 条目名称 | 14px | 15px / 500 |
| 描述 | 12px | 13px |
| 章节头下边距 | 40px | 24px |
| 罗盘尺寸 | 248px | 280px（可交互） |

原则：**紧凑不等于拥挤**——通过栏位对齐和细线维持秩序，而不是靠留白撑空间。

### 惊喜交互清单

1. **指针聚光（Spotlight）**：索引行跟随鼠标出现极淡的蓝色径向高光，移出即消失（仅 hover 反馈，不用于页面背景）。
2. **交互式罗盘**：Hero 罗盘指针跟随鼠标方位转动；点击罗盘触发「随机航向」——全屏短暂航线动画后打开一个随机站点。
3. **随机发现（Random Dock）**：页面右下角常驻「随机发现」按钮，点击后展示寻路动画并打开随机条目；键盘快捷键 `R`（非输入态）。
4. **数字滚动（Count-up）**：Hero 统计数字首次进入视口时从 0 滚动到目标值，200ms stagger。
5. **资讯跑马灯（Signal Ticker）**：顶部细条滚动最新资讯标题，hover 暂停。
6. **检索增强**：命令面板结果逐行淡入、保留匹配词高亮；支持 ↑↓ 选择、Enter 打开。
7. **滚动进度**：左侧轨道顶部细线随页面滚动填充，指示当前阅读进度。
8. **主题切换**：图标旋转 + 颜色过渡，写入 localStorage。

所有动效遵守 `prefers-reduced-motion`：开启时全部退化为静态，随机发现直接打开链接。

## 7. 反模式（明确不做）

- ❌ 居中 Hero + 两个 CTA 按钮的通用落地页结构
- ❌ 圆角卡片网格 + 大投影 + 彩色渐变
- ❌ pill 胶囊标签墙、emoji 图标、插画素材
- ❌ 把内容隐藏在客户端 JS 里（影响 SEO）
- ❌ 为了「与众不同」牺牲可读性与键盘可用性
